# Golden files

These files pin the public behavior of REST v1 and `pgconfigctl`. They were
recorded from the Go binaries at `4027cce`, and every later implementation has
to reproduce them.

## Layout

- `rest/*.jsonl`: one HTTP exchange per line: method, request target, status,
  and body.
- `cli/*.jsonl`: one `pgconfigctl` run per line: arguments, exit code, and
  stdout.

`rest/matrix-pg-<version>.jsonl` holds the full product of PostgreSQL version,
profile, disk type, RAM, and CPU. The other files sample one concern each:
formats, pgbadger, documentation, operating system and architecture, input
parsing, routing, and errors.

The cases are generated by `crates/golden/src/cases.rs`.

## How outputs are compared

- JSON is compared after parsing. Go escapes `<`, `>`, and `&`, and other
  encoders do not.
- Text is compared byte for byte.
- The build version is replaced with a placeholder on both sides: the
  `Generated by PGConfig` header, `meta.version`, the `/v1/version` payload,
  and the `pgconfigctl version` line.
- A failed CLI run pins only its exit code. The wording of usage errors belongs
  to the argument parser.
- Every request carries `Host: golden.pgconfig.test`, because v1 echoes the
  host in `links.self`.

## Check

Build the binaries, then replay every record against them:

```sh
make build
cargo run -p pgconfig-golden -- check \
  --server-bin dist/api --cli-bin dist/pgconfigctl
```

The check also fails when the stored requests differ from the generated cases.

## Record again

Record only after an intended change to the rules or to the cases, and review
the diff like any other change:

```sh
cargo run -p pgconfig-golden -- record \
  --server-bin dist/api --cli-bin dist/pgconfigctl
```

Recording twice from the same binaries produces identical files.

## What the goldens leave out

- `max_connections=0` and values that overflow a 64-bit integer. The Go result
  depends on the CPU architecture.
- The Swagger UI under `/docs`. Its markup belongs to the generator.
- The leak described in `cases.rs` next to `docs`: after one request with both
  `show_doc` and `include_pgbadger`, the Go API adds an empty `documentation`
  object to every later pgbadger response. The request that triggers it runs
  last, so its aftermath is never recorded.
